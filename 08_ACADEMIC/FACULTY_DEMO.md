# Faculty Demonstration Brief

## Project
**GuardianX — Elderly Remote Safety**

**Presented by:** Sunaina Mohapatra  
**USN:** ENG24CT0058  
**Stage:** Concept and interactive software prototype

## Problem statement
Older adults living alone may be unable to request help after a fall or other urgent event. Family members may live remotely and lack a unified way to understand device status, review potential incidents, and coordinate a response.

## Proposed solution
GuardianX explores a wearable-powered system that can detect potential safety events, assess data quality and context, initiate a check-in workflow, notify authorised trusted contacts, and record follow-up actions in one dashboard.

## Key differentiator hypothesis
The project focuses on a connected response workflow, not only sensor detection: event → context check → check-in → ordered contact escalation → acknowledgement → outcome history. This is a hypothesis to validate; existing products already provide some fall detection and emergency response capabilities.

## Current prototype demonstrates
- Product concept and responsive landing page.
- Proposed sensor-to-response architecture.
- Simulated family dashboard.
- Simulated fall and inactivity events.
- Alert state and response workflow concept.
- Academic project metadata and future roadmap.

## Not implemented yet
- Physical wearable or live sensor feed.
- Validated fall/inactivity detection.
- Real authentication or database persistence unless separately built after this handoff.
- Real SMS, push, voice, doctor, ambulance, or emergency dispatch.
- Clinical validation or regulatory clearance.

## Suggested 3-minute walkthrough
1. **0:00–0:30 — Problem:** explain the gap between an event and response.
2. **0:30–1:00 — Product:** show wearable → assessment → family dashboard.
3. **1:00–1:45 — Demo:** open dashboard and explain sample status.
4. **1:45–2:20 — Simulate event:** trigger a potential fall; inspect alert and audit timeline.
5. **2:20–2:45 — Response workflow:** simulate check-in/contact escalation and resolve with an outcome.
6. **2:45–3:00 — Honesty and roadmap:** state that hardware, algorithms, and real emergency integrations remain future work.

## Questions to prepare for
- What sensors would be used and why?
- How do you distinguish a fall from dropping a device?
- How do you avoid false alarms?
- How does the system know whether inactivity is unusual?
- What happens if internet or battery fails?
- How will privacy and consent be handled?
- How is this different from Apple Watch or medical alert products?
- How would emergency services be integrated safely?
- What evidence is required before claiming accuracy or safety benefits?
